## 갱신 규칙

- **작업을 시작할 때**(브랜치를 만들 때): "지금 진행 중"에 한 줄을 더하고, Phase 판의 그 칸을 `진행 중`으로 바꾼다.
- **PR을 열 때**: 그 줄에 PR 번호를 적는다.
- **머지했을 때**: "지금 진행 중"에서 줄을 빼고, Phase 판을 `끝`으로 바꾼다. 화면 상태를 바꿨다면 gui-screens §0도 같은 PR에서 고친다(정본).
- **디자인 근거가 바뀌었을 때**(Ready for dev 추가·제거, 새 Design Sync 이슈): Phase 판의 근거 칸과 "디자인 근거 집계"를 고친다.
- 맨 위 "마지막 갱신" 날짜와 한 줄 사유를 고친다.
- 오프로드한 세션(Orca)은 자기 브랜치에서 자기 줄만 고친다 — PR에서 Phase 판·"다음 순서"의 자기 줄을 `끝`(PR 번호)으로, "지금 진행 중"에서 자기 줄을 뺀다.
- 관제탑만 아는 변경(새 킥오프 줄, 이슈·Ready 수, 순서 변경)은 관제탑이 작은 docs PR로 모아 낸다(스킬 `main-phase` ⑦). 관제탑은 `main`에 직접 커밋하지 않는다.
