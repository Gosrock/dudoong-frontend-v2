## 3. 데스크탑 — `Desktop - 27`(`14:1304`, 1440×1024)

등록 후 공연의 **대시보드**다. 모바일 `525:3903`의 PC판이다.

| 영역 | 폭 | 내용 |
|---|---|---|
| 좌측 사이드바 | 255 | 검정 배경. 로고, "호스팅 홈", 섹션 "공연"(대시보드·기본 정보·상세 정보·티켓 관리·예매자 관리·QR 체크인), 섹션 "호스트", 맨 아래 아바타 + 닉네임·호스트 이름. 메뉴 항목은 원격 `Component 1`(아이콘은 자리표시) |
| 본문 | 약 793 | 제목 바, 포스터 + 공연 정보(일자·시간·러닝타임·장소·태그) + 공개 상세로 가는 ↗, "티켓 승인 정보" 2×2 카드(각 ↗), "티켓 판매 정보" 도넛 + 범례 + 총액 |
| 우측 패널 | 약 392 | **모바일에 없는 요소** — "공연 일정" 주간 달력, 단계 타임라인(공연 등록 → 공연 홍보 및 티켓 판매 → 공연 시작 → 공연 완료, 현재 단계 강조 + 일러스트), 입장 현황 |

`desktop-lg grid`(12 / 24 / 80)가 붙어 있지만 3단 배치는 그리드를 따르지 않는다.

**계획에 주는 뜻**
- 호스팅 센터는 PC 레이아웃이 있다. **고정 좌측 사이드바 + 본문 + 우측 보조 패널**이다. design-requests Q2는 "일부 해결"이고, 남은 PC 화면의 FE 잠정안은 "사이드바 + 본문 1단"이다.
- PC에서 공연 메뉴는 사이드바, 모바일에서는 햄버거 + 공연 전환 헤더다. 공연 스코프 레이아웃이 브레이크포인트로 둘을 나눈다.
- 사이드바에 "호스팅 홈"·"호스트" 섹션이 있어 호스팅 전역 사이드바로 보인다.
- PC 시안은 **대시보드 1장뿐**이다. 홈·폼·티켓·예매자 표의 PC 배치는 없다.
- 3단(255 + 793 + 392)은 1024 폭에 들어가지 않는다. 1024~1279 구간의 중간 배치(예: 우측 패널을 본문 아래로)를 P1 브레이크포인트와 함께 정한다.
- 노드 id가 이 페이지에서 가장 이르고 공연명(29회)이 모바일(30회)과 달라 **초기 시안일 수 있다**. 최신 여부를 디자이너에게 확인한다.
- 우측 단계 타임라인의 "홍보 및 티켓 판매" 기간을 어느 값으로 그리는지 정해지지 않았다(등록일 ~ 공연 시작으로 추정).

## 4. GUI와 서버가 다른 것 — 프론트 보정(핸드오프)

디자이너 메모 `103:2066`이 요청한 핸드오프 목록은 **원본은 [`design-requests.md`](./design-requests.md) §3**이다. 여기에는 GUI 화면에 해당하는 것만 요약한다.

- 체크아웃: 예매번호·티켓번호 줄을 빼고, 결제은행 줄을 더하고, CTA는 "결제하기"(두둥 티켓) · "신청하기"(무료)
- 주문상세: 할인금액을 빼고, 승인 대기는 보라판에서 티켓번호·티켓상태 두 줄만 뺀다(옵션 응답·예매번호는 둔다, Q15), 결제방식은 하나만, [주문취소]·환불 계좌 입구는 계획대로 만든다(Q11)
- 알림함: 서버 문구 그대로, 카테고리 아이콘만 GUI대로(리마인드 알림은 v2에 없다)
- 정렬 드롭다운은 고정 라벨, 미로그인 햄버거 항목(벨 포함)은 `/login?redirect=…`, 태그는 GE-11 응답으로 그린다
- 티켓 폼: 라벨 "두둥 티켓 / 무료 티켓", 무제한이면 재고 공개를 강제로 끈다, 은행은 목록, 관리자 승인 토글은 무료일 때만 연다
- 호스트: 연락처에 유튜브 추가, "호스트 삭제하기" 없음, 소개글 255자
- 대시보드: 입장 분모는 발급 수, 유의사항 문구는 서버 잠금 규칙(판매 또는 승인 대기 주문, 일부 필드는 수정 가능)대로
- 공연준비 홈: 공연 생성 뒤에는 대시보드로(Q7), 카드 ⋮는 준비중 공연 + 매니저 이상일 때만
- 등록 후 잠기는 필드(GUI 메모 `337:2464` "[티켓 판매 전] 전부 바꿀 수 있음"): 서버 기준 — 공연은 "티켓 여부"만, 티켓은 판매나 승인 대기 주문이 생기면
- 일정: 날짜 하나 + 시작·종료 시각에서 종료가 시작보다 이르면 다음 날로 계산
