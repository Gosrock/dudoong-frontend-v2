# DuDoong v2 — 디자인·기획 요청

> 2026-10-15 작성. 프론트 v2 계획을 백엔드 통합 기획서(2026-10-10), 백엔드 `dev` 코드, 기획서에 딸린 와이어프레임 이미지 62장과 대조하면서 나온 것이다.
> 노드 번호(`424:9918` 등)는 와이어프레임 V0.9 파일(`YQzHNU46AMT4iXlKuM4LnH`)의 프레임이다. 그 뒤 Figma가 바뀌었는지는 확인하지 않았다.

디자인 시스템 파일(토큰·컴포넌트)에 대한 정리 요청은 [`design-system.md`](./design-system.md) §5에 따로 있다.

이 문서는 세 부분이다.

1. **화면이 없는 것** — 프론트가 그릴 근거가 없다. 디자인이 필요하다.
2. **기획 질문** — 화면을 그리기 전에 정할 것.
3. **Figma와 서버가 다른 것** — 프론트는 서버 기준으로 만든다. Figma를 고쳐 주면 된다.

각 항목의 "FE 잠정안"은 답이 오기 전까지 프론트가 그 방식으로 만든다는 뜻이다. 답이 오면 바꾼다.

---

## 1. 화면이 없는 것

### 관객

| 화면 | 필요한 이유 | FE 잠정안 |
|---|---|---|
| 선물 랜딩의 상태 5종 — 이미 받음(`ALREADY_ACCEPTED`), 거절됨(`REJECTED`), 반환됨(`RETURNED`), 내가 보낸 링크(`OWN_LINK`), 만료(`EXPIRED`) | 서버는 7가지 상태를 준다. Figma에는 받기 전(`128:1784`)과 취소됨(`128:1811`)만 있다 | 상태마다 안내 문구 한 줄 + 티켓탭으로 가는 버튼. `OWN_LINK`·`EXPIRED`에서 보낸 사람이면 [선물 회수] |
| 거절된 주문의 환불 계좌 입력 입구 | 호스트가 거절하거나 승인 후 취소한 유료 주문은 관객이 환불 계좌를 넣어야 한다(입금 미확인 거절은 제외) | 주문상세 상단에 "환불받을 계좌를 입력해 주세요" 안내 + [계좌 입력] |
| 보낸·받은 선물 내역 | 서버 API(GG-7)가 있다. Figma에 화면이 있는지 확인하지 못했다 | 화면이 있으면 `/mypage/gifts`로 만든다. 없으면 만들지 않는다 |
| 진행 중 공연 배지 | 공연 표시 상태에 "진행 중"이 있다 | 기존 배지 스타일에 색만 바꿔 쓴다 |
| 회원 탈퇴 메뉴 | 탈퇴 API가 있고 탈퇴하면 보낸 대기 중 선물이 취소된다 | 마이페이지 하단 텍스트 버튼 + 확인 모달(선물 취소 안내 포함) |
| 관심 호스트 필터, 주문내역 필터의 선택지 | 관심 호스트는 서버가 전체/공연 있음/공연 없음(`ALL`·`ACTIVE`·`ENDED`)으로 거른다. 주문내역 필터는 디자이너 확인 목록에 있었다 | 관심 호스트: 서버 3값을 탭으로. 주문내역: 필터 없이 최신순 |

### 호스팅 센터

| 화면 | 필요한 이유 | FE 잠정안 |
|---|---|---|
| QR 체크인 결과 화면 | 호스트 스캔 결과가 5가지로 온다 — 입장 완료, 이미 입장, 다른 공연 티켓, 취소된 티켓, 선물 수락 대기 티켓 | 결과마다 아이콘 + 문구 한 줄 + 다음 스캔 버튼 |
| 예매자 관리의 환불 탭 | Figma(`424:11710`, `424:12014`)는 "주문 / 발급된 티켓" 두 탭뿐이다. 서버에는 환불 목록(GF-1)이 따로 있다 | 세 번째 탭 "환불"(`?tab=refunds`). 표 형식은 주문 탭과 같게 |
| 예매자 관리 주문 상태 탭 | Figma(`424:12165`)는 전체/승인대기/승인 완료/승인 거절 4개다. 서버 상태는 6개(취소·실패 포함) | 취소 탭을 더해 5개. 실패(`FAILED`)는 무료 선착순 확정 실패라 보이지 않는다 |
| 호스트 주문 상세의 나머지 영역 | Figma(`503:27255`)는 티켓별 옵션 응답만 있다. 주문자 정보, 환불 계좌, 수정 시각, [승인]·[주문 취소]·[환불 완료] 버튼이 필요하다 | 옵션 응답 위에 주문자 블록, 아래에 환불 블록(매니저 이상만 계좌 표시), 하단 고정 버튼 |
| 발급 티켓 상세의 나머지 영역 | Figma(`503:27502`)는 티켓 번호와 옵션 응답만 있다. 입장 상태, 소유자·주문자, 연락처가 필요하다 | 호스트 주문 상세와 같은 구성 |
| 승인 완료 주문 취소 화면, 승인 실패 안내 | 호스트가 승인 후 취소할 때 사유(100자)를 받는다. 승인은 재고 부족이나 1인 제한으로 실패할 수 있다 | 취소: 사유 입력 바텀시트. 승인 실패: "승인할 수 없어요. 거절로 정리해 주세요" 모달 |
| 옵션 상세의 삭제 입구 | Figma(`424:10455`)에는 [수정]만 있다. 서버에 삭제 API가 있다 | 상세 모달 하단 [삭제]. 티켓에 붙어 잠긴 옵션이면 숨긴다 |
| 옵션 수정 화면의 잠금 표시 | 판매가 시작된 티켓에 붙은 옵션은 이름·설명만 고칠 수 있다 | 잠긴 칸은 회색 + 자물쇠 아이콘 |
| 종료 날짜 입력 | Figma(`424:9659`, `424:9918`)는 날짜 하나 + 시작·종료 시각이다. 서버는 자정을 넘는 공연 때문에 시작·종료를 각각 날짜+시각으로 받는다(기획서 F2가 디자인 요청으로 남김) | 종료 시각이 시작 시각과 같거나 이르면 다음 날로 계산하고, 입력칸 아래에 "다음 날 02:00 종료"처럼 보여 준다 |
| 티켓 폼 기본값, 은행 선택 UI | Figma 기본값(무제한 + 재고 공개)은 서버가 거부하는 조합이다. 은행명은 지금 자유 입력이라 토스 송금 링크를 만들 수 없다 | 기본값은 "수량 지정 + 재고 공개". 은행은 목록에서 고르게 한다 |

## 2. 기획 질문

| # | 질문 | 답이 없으면 |
|---|---|---|
| Q1 | 알림을 누르면 어디로 가나? 알림에는 종류와 대상 id만 온다 | 주문 알림 → 주문상세(호스트가 받은 알림은 예매자 관리의 주문 상세), 선물 알림 → 티켓탭, 멤버 추가 알림 → 호스트 홈 |
| Q2 | 호스팅 센터에 PC 레이아웃이 필요한가? 와이어프레임은 전부 모바일 프레임이다 | 모바일 레이아웃을 PC에서 가운데 정렬해 보여 준다 |
| Q3 | 공연 기본 정보 폼(`424:9918`)의 "카카오 지도" 영역을 그리나? 좌표는 주소 검색으로 얻으므로 지도는 확인용이다 | 그리지 않는다. 주소 검색 결과 텍스트만 보여 준다 |
| Q4 | 햄버거 메뉴(`454:556`)의 AD 배너와 "서비스 업데이트 노트"는 무엇을 보여 주고 어디로 가나? API에도 기획서에도 없다 | 그리지 않는다 |
| Q5 | 모바일에서 바텀시트가 열린 채 뒤로가기를 누르면 시트만 닫히나, 화면을 떠나나? | 화면을 떠난다(구현이 가장 단순하다). 시트만 닫기로 하면 주문 상세 모달도 같이 바꾼다 |

## 3. Figma와 서버가 다른 것

프론트는 "프론트 구현"에 적은 대로 만든다. Figma만 맞춰 주면 된다.

| 노드 | Figma | 서버 | 프론트 구현 |
|---|---|---|---|
| `503:30950` 권한 가이드 | "호스트 삭제 — 마스터" 행 | 호스트 삭제 기능이 없다 | 그 행을 뺀다 |
| `503:31067` 멤버 초대 | "상대방 승인 후 멤버 목록에 표시됩니다" | 초대하면 바로 멤버가 된다 | "바로 멤버로 추가돼요"류 문구 |
| 호스트 만들기·설정 | 소개글 100자 | 255자 | 255자 |
| `128:2583` · `128:2646` · `128:2709` 주문상세 | 거절된 주문에도 [주문취소] | 거절된 주문은 취소할 수 없다 | 버튼을 숨긴다 |
| `498:703` 주문상세(선물중 티켓 포함) | [주문취소] | 선물 대기·완료 티켓이 있으면 취소할 수 없다 | 버튼 대신 "선물을 먼저 취소하거나 돌려받아 주세요" |
| `128:2263` 승인 대기 주문상세 | 티켓번호·티켓상태 줄 | 티켓은 승인 때 발급된다. 승인 대기 주문에는 티켓이 없다 | 옵션 응답만 그린다 |
| `424:11361` · `424:11427` 입장 현황 | 분모 50(판매 수량으로 보임) | 분모는 발급된 티켓 수 | 발급 수로 그린다. 발급 0이면 0/0 |
| `424:10517` 옵션 수정 | 응답 형식 버튼(주관식/네·아니오)을 바꿀 수 있다 | 형식은 만든 뒤 바꿀 수 없다 | 읽기 전용으로 그린다 |
| `128:678` · `455:8958` 정렬 | "공연임박순 ⌄" 드롭다운 | 정렬 기준이 하나뿐이다 | 드롭다운 없이 고정 라벨 |
| `455:8935` 선물 링크 공유 | [메세지] [카카오톡] [링크복사] | 기획서에는 2개 | Figma대로 3개. [메세지]는 문자 앱을 연다 |
| `454:556` 햄버거 메뉴 | 호스트 아바타 줄, 빠른 공연·호스트 만들기 | 소속 호스트는 최대 10개 + 전체 수 | 그대로 만든다(AD·업데이트 노트는 Q4) |
| 등록 후 잠기는 필드 | 여러 필드가 잠김 | 등록 후에는 "티켓 여부"만 잠긴다 | 서버 기준 |
