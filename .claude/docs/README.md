## 미확정

### 누군가의 답이 필요한 것

백엔드에 물으려던 것 중 코드로 답이 나온 것은 [`tech-decisions.md`](./tech-decisions.md) §23에 있다(쿠키 세팅 주체, 옵션 필수 여부, 은행명 형식 등). 아래는 코드로 알 수 없어 남은 것이다.

**백엔드**

| # | 질문 | 왜 필요한가 |
|---|---|---|
| B1 | 리프레시 토큰이 사용자당 하나만 유효한데(다른 기기에서 로그인하면 기존 기기의 재발급이 실패) 의도인가? | 폰으로 티켓을 보는 사람이 노트북으로 호스팅 센터에 들어오면 한쪽이 끊긴다. 의도면 FE는 안내 문구만 둔다 |
| B2 | 운영의 액세스·리프레시 토큰 수명(`JWT_ACCESS_EXP`, `JWT_REFRESH_EXP`)은? 코드 기본값은 둘 다 3600초다 | 세션 유지 UX와 재발급 주기 |
| B3 | 티켓 계좌의 은행명을 목록(코드값)으로 바꿀 수 있나? 지금은 자유 입력 30자다 | 토스 송금 링크에 넣을 은행명을 만들 수 없다. 어렵다면 FE 폼에서 목록으로 제한한다 |

### FE가 조사할 것

2026-10-12에 조사했다. 결과는 [`tech-decisions.md`](./tech-decisions.md) §22.

| 항목 | 결과 |
|---|---|
| ky에 넘긴 캐시 옵션이 Next 캐시에 걸리는지 | 걸린다. §4 설계 전체를 돌려 확인 |
| vanilla-extract 개발 서버와 Storybook | 동작 |
| `notFound()`가 크롤러에게 200으로 나가는 원인 | 풀림. `generateMetadata`도 `serverQuery`를 쓰고 `loading.tsx`를 두지 않으면 404 |
| 마크다운 렌더러 | `marked` |
| 0.x 라이브러리 2종 | 쓰지 않는다 |
| v1이 쓰던 라이브러리의 React 19 동작 | 문제없음 |
| v1 라우트와 리다이렉트 표 | 작성. `/meta/term`·`/meta/privacy` 정적 파일을 옮겨 와야 한다 |
| 토스 송금 링크 규격 | 비공식 스킴 `supertoss://send?bank=&accountNo=&amount=`. **실기기 확인 필요** |

**남은 것** — 실제 환경이 있어야 확인할 수 있다.

| 항목 | 필요한 것 | Phase |
|---|---|---|
| 토스 송금 링크가 실제로 열리는지, 은행명 값이 맞는지 | 토스 앱이 깔린 기기 | P7 |
| 카카오 스크랩 서버의 현재 UA와 미리보기 | 카카오 공유 디버거 + 공개 URL | P5b |
| `SameSite=Strict`에서 카카오 로그인 복귀 직후 쿠키 | 스테이징 | P4b |
| v1 본문 실데이터가 `marked`로 제대로 렌더되는지 | 백엔드 데이터 샘플 | P5b |
| 실제로 유통된 v1 URL | 접근 로그 | P15 |

### 디자인 대기

백엔드 문서의 "디자이너 확인 25건"(2026-10-05·09 기준) 중 화면이 없어 FE가 그릴 수 없는 것만 추렸다. 이후 Figma 변경 여부는 확인하지 않았다.

- QR 체크인 결과 화면
- 선물 랜딩 `viewState` 5종(ALREADY_ACCEPTED · REJECTED · RETURNED · OWN_LINK · EXPIRED)
- 거절 주문상세의 환불 계좌 입력 입구
- 승인 완료 주문 취소 화면, 승인 실패 안내
- 티켓 폼 기본값(무제한 + 재고 공개 — 서버가 거부하는 조합)
- 진행 중 공연 배지, 회원 탈퇴 메뉴, 옵션 수정 화면 잠금 표시
- 주문내역 필터, 관심 호스트 필터 선택지
- PC 레이아웃 범위(와이어프레임은 호스팅 센터까지 모바일 프레임)

### 지켜볼 것

결정할 것은 아니지만 바뀌면 화면이 달라진다.

- 백엔드 "기본안"(변경 가능) 항목: 입금자명 닉네임 고정, 받은 티켓 재선물 불가, 공연 검색 범위 등
- #758: 엑셀 다운로드 매니저 이상, 일반 멤버에게 연락처·이메일 가림, 일부 400 → 404
- #776: Origin 검사, OAuth `state` 필수, 토큰 쿠키 HttpOnly
- 셀프 체크인 경로 `/check-in` — 서버 응답에 박혀 있으나 백엔드 문서에는 "협의 필요"로 남아 있다

### 구현하면서 정할 것

신규 라우트 경로(`/events`, `/events/[eventId]/checkout`, `/hosts/[hostId]`, `/mypage/following`, `/mypage/archive`)는 제안대로 진행한다. 주문 완료 화면의 라우트, 쿼리 `staleTime` 기본값, 변형(variant) 작성 규칙은 해당 Phase에서 정한다.
